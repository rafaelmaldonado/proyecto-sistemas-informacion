Proceso y validación de conocimiento

Defender el prototipo con evidencia

La meta no es confirmar que el ejemplo funciona, sino intentar refutarlo, explicar por qué funciona y transferir la idea a otro caso.

1. Separar requisito, decisión y evidencia

TipoAfirmaciónCómo se comprueba
Requisito documentadoEl diseño incluye prototipos de entrada y salida; desarrollo incluye código, BD y repositorio.Consigna y matriz de trazabilidad.
Inferencia técnicaConectar alta y consulta permite demostrar coherencia entre interfaz, código y BD; no implica construir todo el CRUD.Captura propia y trazabilidad con RF-01.
Decisión técnicaEste ejemplo usa JavaScript en navegador y servidor, más SQLite; no son tecnologías obligatorias.server.js, schema.sql y justificación según el entorno.
Control de sesgo: no confundas una decisión del ejemplo con una obligación oficial ni una ejecución exitosa con comprensión.

2. Explicar el recorrido

  1. El formulario reúne ID, nombre y raza, como el prototipo de entrada.
  2. app.js convierte los campos a JSON y hace POST /api/perros.
  3. server.js vuelve a validar los datos y ejecuta un INSERT parametrizado.
  4. SQLite conserva el registro y su clave primaria impide IDs repetidos.
  5. La interfaz hace GET /api/perros; el servidor ejecuta SELECT y la tabla muestra el resultado.

3. Intentar refutar antes de aceptar

PruebaPredicción escrita antes de ejecutarEvidencia esperada
Registrar un ID nuevo.¿Qué capas participan y qué debe cambiar?Mensaje, nueva fila y registro en SQLite.
Repetir el mismo ID.¿Qué capa debe rechazarlo y por qué?Error visible y una sola fila en la BD.
Enviar nombre vacío o ID cero.¿Qué valida el navegador y qué valida el servidor?No se crea el registro aun si se evita la interfaz.
Recargar la página.¿Debe conservarse la información?El listado vuelve a consultar el archivo SQLite.

Contrasta tres fuentes: la pantalla, la prueba automatizada y una consulta directa con sqlite3. Si discrepan, no elijas la que confirma tu expectativa: investiga la diferencia.

4. Validación para la defensa

Otra persona marca cada criterio durante una demostración sin apuntes. “Lo vi en el código” no cuenta como explicación.

Preguntas de seguimiento del evaluador
  • ¿Por qué se valida en HTML y otra vez en el servidor?
  • ¿Qué evita que dos perros tengan el mismo ID?
  • ¿Por qué el SQL usa signos ? en lugar de concatenar texto?
  • ¿Qué diferencia existe entre memoria del navegador y persistencia en SQLite?
  • ¿Qué evidencia demuestra el INSERT y cuál demuestra el SELECT?
Puerta de salida: presenta sólo cuando completes los cinco criterios dos veces: una con el recorrido normal y otra con un dato inválido elegido por el evaluador.

5. Seguridad sin afirmar HTTPS

Este prototipo usa HTTP local. La evidencia de cifrado es el respaldo creado por backup.js; HTTPS queda como módulo futuro si la aplicación se publica.

  • Crea un respaldo, restáuralo con la clave correcta y muestra el archivo resultante.
  • Predice y demuestra qué sucede con una clave incorrecta.
  • Explica por qué la contraseña no está escrita en el repositorio.
