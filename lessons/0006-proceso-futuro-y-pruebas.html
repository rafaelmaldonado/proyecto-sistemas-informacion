Prototipo ejecutable y alcance futuro

La evidencia debe coincidir con lo que realmente existe. Este prototipo implementa inicio, alta y consulta de perros con Node.js y SQLite; los demás módulos se presentan como trabajo futuro, no como funciones terminadas.

Árbol de archivos implementado

code/
├── index.html                        # instalación y ejecución paso a paso
├── defensa.html                      # validación de conocimiento
├── server.js                         # servidor HTTP y API de perros
├── backup.js                         # respaldo cifrado y restauración
├── database/
│   ├── schema.sql                    # tablas, PK, FK y restricciones
│   ├── seed.sql                      # datos de ejemplo opcionales
│   └── centro-adopcion.db            # se crea al ejecutar; no se publica

│   ├── perros.html                   # interfaz de salida
│   ├── styles.css                    # contraste, texto y distribución

│   └── js/

Evidencia: muestra este árbol real, las tres pantallas abiertas desde http://localhost:8000, las tablas y el resultado de las pruebas. No agregues archivos vacíos para completar una captura.

Cómo ejecutar el prototipo

  1. Instala Node 24 LTS y comprueba la versión con node --version.
  2. Desde la raíz del proyecto ejecuta node code/server.js.
  3. Mantén la terminal abierta y visita http://localhost:8000.
  4. Detén el servidor con Ctrl + C antes de cerrar.

Las instrucciones completas de instalación, ejecución y pruebas están en Código de ejemplo ejecutable.

Privacidad y cifrado coherentes con un prototipo local

Aviso base para adaptar: “[Nombre de la organización] recaba [datos] para [finalidad]. No los comparte sin autorización. La persona puede solicitar acceso, corrección o eliminación mediante [contacto del responsable]”.

HTTPS no está implementado en este prototipo local. La dirección usa http://localhost:8000. HTTPS se propondrá sólo si la versión final se publica en un servidor; no debe presentarse como evidencia actual.

La medida implementada es el respaldo cifrado. La contraseña se entrega mediante la variable temporal BACKUP_PASSWORD, nunca se escribe dentro del código ni se publica.

macOS o Linux

BACKUP_PASSWORD='una-clave-larga-y-privada' node code/backup.js crear
BACKUP_PASSWORD='una-clave-larga-y-privada' node code/backup.js restaurar

Windows PowerShell

$env:BACKUP_PASSWORD='una-clave-larga-y-privada'
node code/backup.js crear
node code/backup.js restaurar
Remove-Item Env:BACKUP_PASSWORD

La restauración escribe centro-adopcion.restaurada.db y nunca sobrescribe la base activa. Para la evidencia, demuestra que la clave correcta restaura y que una clave distinta falla.

Ética y mantenimiento

  • Usa únicamente datos ficticios en el repositorio, las capturas y las pruebas.
  • No publiques la base .db, el respaldo .enc ni la contraseña.
  • Permite corregir o eliminar información cuando el módulo correspondiente exista.
  • Mantén accesibilidad, exactitud y respaldo como compromisos del sistema.

Validación de conocimiento para la defensa

  • Explica por qué localhost usa HTTP y por qué no debes afirmar que implementaste HTTPS.
